本文档记录两项关联升级的完整需求与实现计划，避免上下文压缩后遗失细节。

---

## 0. 动机

当前在线转写用 `paraformer-realtime-v2`（传统 ASR，真流式、低延迟、中文强）。
但用户场景是 **中英混读 + 技术专业名词**，Paraformer 在 code-switching 和英文专名上不够准。

调研结论：阿里云 **Qwen3-ASR-Flash**（LLM 架构 ASR）针对该场景更优，且支持注入
**context（上下文）** —— 把关键词表 / 文档 / 背景描述塞进去，让模型在"听"的阶段就向
这些术语靠拢，对无关文本鲁棒，中英混读更强，走 OpenAI 兼容接口（`input_audio`），
复用项目已有的 `openai` SDK，集成成本低。

代价：`qwen3-asr-flash` 是 **一次性文件识别（非流式）**，按回车停止后才上传识别，
短句约 1~3s，会失去 Paraformer 的"边录边传零延迟感"。鉴于用户的工作流是
"录一句 → 回车停止 → 转写"的离散话语，一次性识别可接受，精度收益更值。

## 1. 在线 ASR 引擎升级

### 1.1 目标
把在线转写主引擎换成 **Qwen3-ASR-Flash**，转写时携带"上下文三件套"提升精度。

### 1.2 上下文三件套（context）
转写前拼成 context 交给 Qwen：

1. **今天的长期记忆**（见第 2 节）—— 拍平成一段文本。
2. **已写入文稿** —— 程序当前已撰写出来的内容；过长时只取最近窗口（最后 N 段）。
3. **易错词表** —— 即 [T] 录入的专业/易错名词。

### 1.3 引擎分层（保留兜底）
- **在线主引擎**：Qwen3-ASR-Flash（带 context）。
- **保底**：Paraformer 流式 / 本地 SenseVoice 仍保留，作为对比与离线兜底。
- 离线模式逻辑（已实现）不变：无网时只录音+本地转写，AI 功能隐藏。

### 1.4 接口要点
- OpenAI 兼容 `chat.completions`，音频走 `input_audio`。
- context 作为 system / 文本背景注入。
- 复用现有 `openai` SDK 与 `OPENAI_API_KEY` 体系？注意：Qwen 走 DashScope，
  需用 `DASHSCOPE_API_KEY` + DashScope 的 OpenAI 兼容 base_url。实现时确认。

## 2. 长期记忆系统（连贯记忆 / 衰减记忆）

### 2.1 定位
ASR 上下文三件套之一。给模型一个"我最近在聊什么领域/话题"的语境画像，
本质是一个 **短期专注、逐渐遗忘** 的记忆模型。

### 2.2 存储结构：按天分片 JSON，每天一串自由记忆
**不分字段、不强制主题/领域/概念**，保持灵活零散：

```json
{
  "version": 1,
  "days": [
    {
      "date": "2026-06-10",
      "items": [
        "用户在写语音转写 CLI SyncListen",
        "在讨论 Qwen3-ASR-Flash 的 context 注入",
        "刚切到设计长期记忆的衰减机制"
      ]
    }
  ]
}
```
- 每天一条记录 = `date` + `items`（自由文本短句列表）。
- 每天 `items` 总字数 **≤ 500 字**。
- 喂给 ASR 时：把 **今天这一条** 的 items 拍平成一段文本（永远只喂今天这条，
  因为它已吸收前 3 天的衰减结果）。

### 2.3 衰减机制（核心）
- 时间最小粒度 = **天**，每天一份。
- **今天这条 = 由「前 3 天记忆」+「当前文稿」+「易错词表」重新生成/重写**。
- 近因加权：越靠近今天权重越高，**具体权重配比交给 LLM 自行拿捏**。
- **生成只看前 3 天**；3 天之前的不再被参考。
- **存储滚动保留 30 天**，超 30 天的那天直接删除。
- 注意两个窗口不同：**生成参考窗口 = 3 天**，**存储保留窗口 = 30 天**。
- **跨天**：按本机时间，跨过零点后触发更新时自动新建当天条目，seed 自前 3 天。

### 2.4 更新触发（两个条件，满足任一即触发一次后台更新）
- **条件 A**：AI 功能累计触发 **5 次**（↵ 回车转录 / S 升华 / A AI修改 / F 词语修复
  均计数），满 5 次触发一次，然后计数清零。
- **条件 B**：按 **[D] 删除** 清空当前文稿区域时立即触发一次。
  **时序：先抓取文稿 → 更新并存档记忆 → 再清空。** 不可先清空（否则丢内容；
  也符合"优先可恢复、别丢数据"原则）。[D] 是用户"任务切换瞬间"的天然快照点。

### 2.5 更新流程
传入 **易错词表 + 当前文稿 + 旧记忆（前 3 天）** → LLM：
- 压缩重写、**可选择性遗忘**（删掉过时/不重要的条目）；
- 产出/刷新 **今天** 这一条的 `items`（≤500 字）。

### 2.6 执行方式：用户完全无感
- 更新在 **后台线程**（不开子进程；LLM 调用是网络 I/O，线程足够无阻塞）。
- 更新完成后终端 **闪烁 "💾 记忆更新" 提示**：连闪两下、约 1 秒，告知用户。

### 2.7 记忆模式 [M]
独立模式键 **[M]**（Memory），进入后可：
- **查看** 当前长期记忆；
- **编辑** 记忆；
- **清空** 记忆。

## 3. 实现计划（分两块，按序）

### 块一：切换 ASR 引擎（先做，可独立验证）
1. 新增可传 context 的 Qwen3-ASR-Flash 云端识别（OpenAI 兼容 `input_audio`）。
2. 把"上下文三件套"拼进 context（记忆系统未做前，先用 文稿+易错词 两件）。
3. 保留 Paraformer / 本地 SenseVoice 作兜底。
4. 验证：中英混读 + 专名样本，对比精度。

### 块二：长期记忆系统（后做）
1. 新增 `synclisten/core/memory.py`：`MemoryStore`
   - JSON 读写、30 天裁剪、取今天 / 取前 3 天；
   - 5 次 AI 计数器；
   - 后台线程更新。
2. `ai_client` 新增 `update_memory(prev_3days, current_doc, terms) -> items`。
3. 接线 `main.py`：
   - 计数器挂到 ↵/S/A/F；
   - [D] 删除前快照更新；
   - 启动加载记忆、退出存盘（跨重启持久化、全局一份）；
   - [M] 记忆模式；
   - "💾 记忆更新" 闪烁提示；
   - 把"今天记忆"接入 ASR context（三件套补齐）。

## 4. 配置项（新增）

| 名称 | 含义 | 默认 |
|---|---|---|
| `QWEN_ASR_MODEL` | Qwen ASR 模型名 | `qwen3-asr-flash` |
| `MEMORY_FILE` | 长期记忆 JSON 路径 | 仓库内数据目录 |
| `MEMORY_RETENTION_DAYS` | 存储保留天数 | 30 |
| `MEMORY_REFERENCE_DAYS` | 生成参考天数 | 3 |
| `MEMORY_DAY_CHAR_LIMIT` | 每天记忆字数上限 | 500 |
| `MEMORY_AI_TRIGGER_COUNT` | 触发更新的 AI 调用次数 | 5 |

（沿用现有 `DASHSCOPE_API_KEY` / `OPENAI_API_KEY`，均在 `.env`，已 gitignore。）

## 5. 已确认决策清单

- ASR 引擎：Qwen3-ASR-Flash + context 注入。
- 喂 ASR 的记忆：永远只喂"今天这一条"。
- 记忆结构：按天分片 JSON，每天 `date` + 自由 `items` 列表，不分字段，≤500 字/天。
- 衰减：今天 = 前 3 天（LLM 近因加权）+ 当前文稿 + 易错词；生成看 3 天，存储留 30 天。
- 触发：AI 累计 5 次 或 [D] 删除（删除前先快照）。
- 执行：后台线程，无感；完成闪 "💾 记忆更新" 两下约 1 秒。
- 记忆模式键：[M]，可查看/编辑/清空。
- 跨天：按本机时间自动新建当天条目。
